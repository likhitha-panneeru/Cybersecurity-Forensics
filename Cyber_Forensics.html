1 — Data Acquisition

1.1 What is Data Acquisition?

Data acquisition is the controlled collection of digital evidence from a device or storage medium so that the evidence can later be examined and presented without changing its original state.

Core forensic principle: collect first, preserve integrity, analyze a verified copy. The original evidence should be protected from unnecessary modification.

Data Storage Fundamentals

Digital evidence can exist on many kinds of storage: HDDs, SSDs, USB drives, memory cards, optical media, NAS/SAN storage, phones, virtual disks and cloud-backed systems. At the logical level, information is organized into files and directories; underneath that, the operating system and file system map those files to storage structures.

ConceptEasy explanationForensic relevance
Bit0 or 1Smallest unit of digital information.
Byte8 bitsBasic unit used to represent data.
SectorSmall addressable storage unitImportant for low-level acquisition.
PartitionLogical division of a diskMay contain different file systems or operating systems.
File systemRules used to organize filesProvides metadata such as names, timestamps and allocation information.
Unallocated spaceStorage not currently assigned to a normal fileMay contain remnants of deleted files.

Introduction to Cyber Crimes

A cyber crime is an unlawful activity involving computers, networks, digital devices or digital information. Forensics helps answer questions such as what happened, when, how, which account/device was involved, and what evidence supports the conclusion?

CategoryExamplePotential evidence
Unauthorized accessCompromised account or systemAuthentication logs, browser history, endpoint artifacts
MalwareTrojan/ransomware infectionFiles, processes, persistence artifacts, memory
Data theftUnauthorized copyingFile timestamps, USB artifacts, network logs
FraudDigital transaction manipulationEmails, logs, application records
DoS/DDoSAvailability attackNetwork captures, firewall and server logs

Cyber Forensics Principles

  1. Integrity: evidence must remain trustworthy and demonstrably unchanged.
  2. Authenticity: show that the evidence is what you claim it is.
  3. Documentation: record actions, times, tools and observations.
  4. Repeatability: another examiner should be able to understand and reproduce the analytical process.
  5. Chain of custody: document who possessed evidence, when, why, and what happened to it.
  6. Minimize alteration: avoid modifying the original evidence.

Digital Evidence Seizure

Seizure is the controlled taking of a device or digital medium into evidence. The exact procedure depends on law, organizational policy and the situation.

  1. Confirm legal authority and scope.
  2. Document the scene and device state.
  3. Record identifiers such as device make/model and serial number.
  4. Decide whether the device is powered on or off; live systems can contain volatile evidence.
  5. Isolate devices from networks when appropriate and authorized.
  6. Use appropriate forensic acquisition procedures.
  7. Label, seal, hash and document evidence as required.

Forensic Hardware Tools

Common hardware includes write blockers, forensic duplicators, evidence storage media, adapters, cables and drive interfaces.

Write blocker: a device or software mechanism intended to prevent writes to a storage medium while an examiner reads it. It is a key evidence-preservation concept.

Seizing Data with Forensic Hardware and Software — Practical

Safe lab exercise: use a spare USB/storage image supplied for training. Do not experiment on someone else's live device.
  1. Connect the evidence medium through a write blocker where applicable.
  2. Identify the source device and record its details.
  3. Calculate a source hash when the acquisition procedure supports it.
  4. Create a forensic image using an approved forensic imager.
  5. Verify the image using a cryptographic hash.
  6. Work from the image/copy, not the original.
  7. Record examiner, date/time, tool/version, source, destination and verification results.
Typical evidence workflow
Evidence → Identification → Preservation → Acquisition → Hash verification
        → Working copy → Examination → Analysis → Reporting
Exam point: acquisition is not the same as analysis. Acquisition obtains/preserves the evidence; analysis interprets it.
2 — Cyber Forensics Analysis

2.1 What is Cyber Forensics Analysis?

Forensic analysis is the examination and interpretation of acquired digital evidence to reconstruct events and answer investigative questions.

Windows File System — FAT and NTFS

FeatureFATNTFS
MeaningFile Allocation Table familyNew Technology File System
Typical useRemovable media and compatibility scenariosModern Windows system volumes
MetadataMore limitedRich metadata and security information
Forensic interestAllocation and directory structuresMFT, timestamps, attributes, security descriptors, journals and more

FAT: keeps allocation information in a File Allocation Table. NTFS: uses the Master File Table (MFT) to maintain records describing files and directories.

Linux File System

Linux systems commonly use file systems such as ext4. Forensics can involve inodes, directory entries, permissions, ownership, timestamps, journaling and deleted/unallocated content.

ArtifactWhat it tells you
InodeMetadata associated with a file, such as permissions, ownership and timestamps.
Directory entryMaps a filename to filesystem metadata.
JournalRecords filesystem transactions useful for reconstruction.
PermissionsShows access rights and ownership.

Familiarizing File-System Concepts — Practical

In a forensic suite, inspect a training image and identify partitions, file systems, directory structures, deleted files, metadata and unallocated areas. Compare the same concept across Windows and Linux evidence.

Tools — Disk Explorer, Win-Hex, Autopsy

  • Disk Explorer: used for examining disk structures and forensic artifacts.
  • WinHex: hexadecimal/disk editor and forensic examination tool; useful for low-level structures and raw data inspection.
  • Autopsy: graphical digital-forensics platform built around The Sleuth Kit; useful for ingesting images and examining file systems, timelines, hashes and artifacts.
Practical learning sequence: open image → identify partitions → browse files → inspect metadata → search keywords → examine deleted/unallocated data → build timeline → document findings.
3 — Disk Forensics

3.1 Disk Forensics Analysis

Disk forensics focuses on persistent data stored on physical or virtual storage. The syllabus specifically includes partitioning, registry, file carving and Windows artifacts.

Partitioning

A partition is a logical region of a disk. Modern systems may use GPT; older systems commonly used MBR. Partition information helps an examiner locate file systems and understand the disk layout.

MBRGPT
Older partitioning schemeModern GUID Partition Table
Partition table has traditional limitationsSupports large disks and many partitions more flexibly

Windows Registry

The Windows Registry is a hierarchical database containing configuration and system/application information. Forensic value depends on the hive and artifact.

  • SAM: local account/security information.
  • SYSTEM: system configuration and control-set information.
  • SOFTWARE: installed software and system/application configuration.
  • SECURITY: security-policy-related information.
  • NTUSER.DAT: user-specific configuration and activity-related artifacts.

File Carving

File carving attempts to recover files from raw data using file signatures and structure rather than relying entirely on the file system's directory metadata.

Why it matters: a deleted file's directory entry may disappear while some or all of its data remains in unallocated space.

Typical carving concepts include file headers/signatures, body/footer patterns, fragmentation and false positives.

Windows Analysis

Browser

Browser artifacts may include history, downloads, cookies, cache, saved form information, session-related data and bookmarks. They can help reconstruct web activity.

Event Log

Windows Event Logs record system and application events. Important categories include authentication, process/service activity, policy changes and system errors. Correlate event times with other artifacts rather than treating one log entry as complete proof.

Prefetch

Windows Prefetch artifacts can provide evidence about program execution and associated files. They are useful for understanding application execution history.

Volume Shadow Copy

Volume Shadow Copy provides point-in-time snapshots of volumes. Older copies may preserve files or artifacts that were later changed or deleted.

Recycle Bin

Deleted files may remain in the Recycle Bin before permanent deletion. Metadata and file contents can help identify what was deleted and when.

Client-Based Email Analysis

Email clients can leave messages, headers, attachments, local databases, caches and configuration artifacts. Important investigative questions include sender/recipient, timestamps, message IDs, attachments and whether the local copy is complete.

Page File

The Windows page file is used for virtual memory. It can contain remnants of data that was previously in memory, although contents and usefulness vary.

Hibernation

The hibernation file stores memory state used to resume the system. It may preserve valuable information from the time the system entered hibernation.

Metadata

Metadata is data about data: timestamps, authors, file properties, camera information, software, GPS information and more. Always distinguish filesystem metadata from application/document metadata.

Spool Files

Spool files are temporary files used by systems/applications to queue jobs such as printing. They may preserve information about documents processed by a system.

Link Files

Windows shortcut/link artifacts can provide evidence about accessed files, paths, volumes and execution/activity context.

Reparse Points

Windows reparse points provide special filesystem behavior, including mechanisms used by links and other filesystem features. Their presence can be significant during filesystem analysis.

Linux Analysis

Linux forensic analysis may examine logs, shell history, authentication records, filesystem metadata, user accounts, scheduled tasks, configuration files and application artifacts.

Practical — Disk Analysis using CyberCheckSuite

  1. Load a training disk image.
  2. Identify partitions and filesystem types.
  3. Browse filesystem contents.
  4. Search for known keywords and file types.
  5. Inspect deleted files and unallocated space.
  6. Examine Windows artifacts and timestamps where present.
  7. Export relevant evidence while maintaining provenance.
  8. Hash exported evidence and record the values.
  9. Create a short finding: artifact → observation → interpretation → limitation.
4 — Live Forensics

4.1 What is Live Forensics?

Live forensics examines a system while it is powered on. This is important because volatile information can disappear when the system is shut down.

Volatile evidencePersistent evidence
RAM contentsDisk files
Running processesFilesystem metadata
Active network connectionsStored logs
Logged-in users/sessionsBrowser/database artifacts

Live Seizing and Acquisition

A live acquisition must balance preservation with the need to capture volatile evidence. Every action performed on a live system can potentially alter evidence, so procedures must be documented.

Live Forensic Analysis

Potential observations include current users, processes, services, network connections, mounted volumes, open files, system time and memory.

Win-LiFT

The syllabus includes Win-LiFT as a live-forensics practical tool. In a lab, use it to understand live evidence collection and artifact capture, following the tool's documentation and the evidence-handling procedure.

Practical Checklist

  1. Photograph/document the system state where applicable.
  2. Record system date/time and examiner time.
  3. Determine what volatile evidence must be captured first.
  4. Collect volatile artifacts with a trusted forensic tool.
  5. Store output on a controlled evidence destination.
  6. Hash and document collected files.
  7. Only then proceed to less volatile examination as required.
Important: “Live” does not mean “free to change anything.” The examiner must minimize changes and maintain a defensible record.
5 — Memory Forensics

5.1 Memory Dumping

A memory dump is a capture of volatile system memory (RAM). RAM can contain running-process information, network state, credentials/tokens, injected code and other transient artifacts.

Memory Analysis

Memory analysis attempts to answer questions such as:

  • Which processes were running?
  • What network connections existed?
  • Which processes had suspicious relationships?
  • Was code injected into a process?
  • What modules, handles or command lines were associated with processes?
  • Are there indicators of malware or persistence?

DumpIt

DumpIt is commonly used for acquiring a memory image from a live Windows system in forensic/incident-response contexts. The resulting image should be preserved and hashed before analysis.

Volatility

Volatility is a memory-forensics framework. A typical investigation uses plugins to enumerate processes, network artifacts, loaded modules and other structures.

Conceptual workflow
Live system
   ↓
Memory acquisition
   ↓
Hash memory image
   ↓
Identify appropriate analysis/profile requirements
   ↓
Volatility analysis
   ↓
Processes / network / modules / suspicious artifacts
   ↓
Correlate with disk + logs
Practical goal: do not memorize only commands. Learn what every output means and how it supports or contradicts another artifact.

Analysis of Live Artifacts — DumpIt, Volatility

For a controlled lab memory image, identify processes and their parent-child relationships, inspect network information, look for suspicious executable paths, and compare findings with known-good baseline behavior.

6 — Network Forensics

6.1 Network Packet Capturing

Network forensics examines network traffic and related records to reconstruct communication and identify suspicious activity.

Packet Basics

A packet is a unit of data transmitted over a network. Depending on the protocol stack, an examiner may inspect Ethernet frames, IP packets and TCP/UDP segments or application-layer information.

Layer/areaUseful information
EthernetMAC addresses, frame information
IPSource/destination IP, protocol, TTL and fragmentation information
TCPPorts, flags, sequence/acknowledgment behavior and connection state
UDPPorts and datagram communication
DNSDomain queries and responses
HTTPRequests/responses when visible and not encrypted

Monitoring and Analysis

Questions include: Who communicated with whom? Which protocol was used? When did communication occur? Was the traffic encrypted? Were there repeated connections, unusual destinations, scans or data-transfer patterns?

Wireshark

Wireshark is a graphical packet-analysis tool. Core skills include opening a capture, filtering traffic, following streams, inspecting protocol fields, viewing timestamps and exporting relevant evidence.

Useful beginner filters in a lab:
ip.addr == 192.0.2.10
tcp
udp
dns
http
tcp.port == 443

Use IP addresses appropriate to your own lab capture; the examples above are documentation/test addresses, not targets.

NeSa

The syllabus lists NeSa for network-forensics work. Learn its role in packet/network capture and analysis according to the lab environment provided.

Practical — Wireshark

  1. Open a provided PCAP.
  2. Identify protocols and endpoints.
  3. Use display filters to narrow the investigation.
  4. Inspect DNS queries and connection timing.
  5. Follow a TCP stream where appropriate.
  6. Identify suspicious or unexpected communications.
  7. Export only the evidence needed and record packet/frame references.
Forensic habit: a packet capture is evidence, not automatically an explanation. Interpret it in context and correlate with host logs and timestamps.
7 — Mobile Phone Forensics

7.1 Mobile Phone Forensics

Mobile forensics is the acquisition and examination of data from smartphones and related mobile components. Evidence can include communications, application data, media, location information and device metadata.

SIM Card Forensics

A SIM/UICC can contain identifiers and subscriber-related information, and depending on the technology and configuration may contain contacts or messages. Modern mobile evidence is much broader than the SIM alone.

Call Data Record (CDR) Analysis

CDR data can contain telecommunications metadata such as calling party, receiving party, timestamps, duration and cell/tower-related information depending on the provider and record type.

Important: CDR is generally metadata, not the audio content of a call. Exact fields depend on the carrier and record format.

Mobile Phone Artifacts

  • Calls and messages
  • Contacts
  • Application databases
  • Photos/videos and metadata
  • Location/GPS artifacts
  • Browser/application history
  • Device identifiers and configuration

MobileCheck, Sim Xtractor, CDR Analyzer

The syllabus lists these as tools for mobile artifact analysis. In the practical environment, learn the acquisition format, supported artifact types, search/export functions and reporting workflow of the supplied versions.

Practical Investigation Workflow

  1. Document the device and its state.
  2. Follow legal authority and acquisition procedure.
  3. Use an approved acquisition method.
  4. Preserve the original acquisition and calculate hashes where applicable.
  5. Parse artifacts with the forensic tool.
  6. Correlate calls, messages, locations and timestamps.
  7. Export findings with source/provenance information.
8 — Malware Analysis

8.1 What is Malware Analysis?

Malware analysis is the examination of malicious or suspicious software to understand what it is, how it behaves, what it changes and what indicators can be used for detection and response.

Static vs Dynamic Analysis

StaticDynamic
Analyze without executing the sample.Observe behavior in a controlled environment.
Hashes, strings, headers, imports, metadata.Processes, files, registry changes, network activity.
Lower execution risk.Requires strong isolation and safety controls.

Useful Malware Concepts

  • Hash: identifies a specific file version/content.
  • IOC: indicator of compromise such as a hash, domain, IP or filename.
  • Persistence: mechanisms used to survive reboot/logon.
  • Command and control (C2): communication between malware and its controlling infrastructure.
  • Packing/obfuscation: techniques that make analysis harder.
  • Behavior: observable actions such as file creation, process spawning or network communication.

Open-Source Tool Categories

PurposeExamples of tools/categories
Hashingsha256sum / platform hashing utilities
Stringsstrings
PE inspectionPEStudio and similar PE-analysis tools
Disassembly/reverse engineeringGhidra, radare2
MemoryVolatility
Network observationWireshark

Safe Practical Lab

Never execute unknown malware on your normal laptop or network. Use an isolated, purpose-built malware-analysis lab with snapshots, restricted networking and known-safe training samples.
  1. Record sample hash and metadata.
  2. Perform static inspection first.
  3. Record strings, file type and suspicious indicators.
  4. If dynamic analysis is authorized, use an isolated VM.
  5. Observe processes, filesystem changes, registry activity and network behavior.
  6. Extract IOCs.
  7. Correlate behavior with endpoint/network evidence.
  8. Produce a concise malware-analysis report.
9 — IoT Forensics

9.1 What is IoT Forensics?

IoT forensics applies digital-forensics principles to connected devices such as cameras, sensors, smart appliances, gateways and other embedded systems.

Protocols and File Systems

IoT devices may use specialized protocols, embedded operating systems and unusual storage formats. Evidence may exist on the device, removable storage, gateway, mobile application, cloud service and network.

Storage and Interfaces

Common interfaces can include flash storage, SD cards, USB, serial interfaces and vendor-specific interfaces. Acquisition must be performed using an appropriate method for the device.

File Systems

Embedded devices may use standard Linux filesystems or specialized/flash-oriented filesystems. The examiner first identifies the storage format before attempting interpretation.

Multimedia Analysis

IoT cameras and similar devices can generate images/audio/video. Examine timestamps, encoding information, file metadata, sequence continuity and potential gaps or manipulation indicators.

GPS Tracking

Location evidence may come from GPS coordinates, application databases, device logs or cloud records. Coordinates must be interpreted with timestamps and the source's accuracy/limitations.

Wi-Fi Cracking — Forensic Context

The syllabus includes Wi-Fi cracking. In a forensic course, the important concepts are wireless authentication, encryption, capture evidence, access-point configuration and lawful recovery/testing of credentials in an authorized lab. Do not attempt to access networks without permission.

Security Challenges

  • Limited storage and processing power
  • Vendor-specific formats
  • Proprietary/cloud dependencies
  • Remote management
  • Weak/default credentials on poorly secured devices
  • Clock/timestamp inconsistencies
  • Encrypted or volatile data
  • Large numbers of distributed devices

IoT Forensics with Open-Source Tools

A practical workflow can combine disk/file analysis, metadata extraction, network capture analysis and timeline correlation. Always identify the source of each artifact: device, SD card, gateway, mobile app, network or cloud export.

Best practice: build an evidence map: Device → Storage → Artifact → Timestamp → Event → Corroborating Source.

How to Correlate Evidence

The strongest forensic conclusions usually come from correlation. For example, a browser artifact may show a visit at one time, a Windows event may show a related logon, a network capture may show communication around the same time, and a memory image may show the related process. None should automatically be treated as definitive alone.
