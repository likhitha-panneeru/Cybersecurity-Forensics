S01

Number Systems, Networking Terms, Cables & NOS

Theory

Binary Number System (Base 2)

Computers only understand binary — 0s and 1s. Each digit is a bit. 8 bits = 1 byte. Every IP address, MAC address, and subnet mask is stored as binary. Understanding binary is essential for subnetting.

Decimal to Binary Conversion

Method: Repeatedly divide by 2 and record the remainder. Read remainders bottom-to-top.

Convert 192 to binary:
192 ÷ 2 = 96  remainder 0
 96 ÷ 2 = 48  remainder 0
 48 ÷ 2 = 24  remainder 0
 24 ÷ 2 = 12  remainder 0
 12 ÷ 2 =  6  remainder 0
  6 ÷ 2 =  3  remainder 0
  3 ÷ 2 =  1  remainder 1
  1 ÷ 2 =  0  remainder 1
Read bottom → top: 11000000 ✓

Quick Method — Powers of 2 Table

Bit Position76543210
Value1286432168421

For 192: 128+64 = 192 → bits 7 and 6 are ON → 11000000

🔶 Self-Learning: Convert 192.168.10.25 to Binary

192 = 128+64               = 11000000
168 = 128+32+8              = 10101000
 10 = 8+2                   = 00001010
 25 = 16+8+1                = 00011001

Answer: 11000000.10101000.00001010.00011001

Binary to Decimal Conversion

Convert 10101000 to decimal:
1×128 + 0×64 + 1×32 + 0×16 + 1×8 + 0×4 + 0×2 + 0×1
= 128 + 32 + 8 = 168 ✓

Hexadecimal Number System (Base 16)

Uses 16 symbols: 0-9 and A-F (A=10, B=11, C=12, D=13, E=14, F=15). Used for MAC addresses, IPv6 addresses, memory addresses, and color codes. Each hex digit = exactly 4 binary bits (nibble).

🔶 Self-Learning: Convert MAC 00-1A-2B-3C-4D-5E

Each hex pair → 8-bit binary:
00 → 0000 0000
1A → 0001 1010   (1=0001, A=1010)
2B → 0010 1011   (2=0010, B=1011)
3C → 0011 1100   (3=0011, C=1100)
4D → 0100 1101   (4=0100, D=1101)
5E → 0101 1110   (5=0101, E=1110)

Full binary: 00000000.00011010.00101011.00111100.01001101.01011110

Where Binary and Hex Are Used in Networking

  • Binary: IP addresses internally, Subnet masks (to separate network/host bits), ACL wildcard masks, Subnetting calculations
  • Hexadecimal: MAC addresses (48-bit, written as 6 hex pairs), IPv6 addresses (128-bit, 8 groups of 4 hex digits), Ethernet frame headers, Wireshark packet analysis, Memory addresses

Networking Terms

Bandwidth

The maximum rate of data transfer across a network link. Measured in bits per second (bps). Think of it as the width of a highway — a 4-lane highway (1 Gbps) can carry more traffic than a 1-lane road (100 Mbps). Bandwidth is theoretical maximum, not actual speed.

Throughput

The actual amount of data successfully transferred per unit time. Always ≤ bandwidth. Affected by congestion, errors, protocol overhead, latency. If bandwidth is the highway width, throughput is the number of cars actually passing per hour.

Latency

The time delay for a packet to travel from source to destination. Measured in milliseconds (ms). Components: Propagation delay (speed of light in medium), Serialization delay (putting bits on wire), Processing delay (router/switch processing), Queuing delay (waiting in buffer). Lower = better. Measured with ping.

Jitter

The variation in latency over time. If latency is usually 20ms but sometimes jumps to 100ms, jitter is high. Critical for real-time apps: VoIP, video calls, gaming. High jitter = choppy calls, lag spikes.

MTU (Maximum Transmission Unit)

The largest packet size a network link can carry without fragmenting. Default Ethernet MTU = 1500 bytes. If a packet exceeds MTU, it must be fragmented (broken into smaller pieces) — or dropped if DF (Don't Fragment) bit is set. Fragmentation hurts performance.

Other Essential Terms

  • Protocol: A set of rules defining how data is formatted, transmitted, and received (TCP, IP, HTTP, DNS).
  • Packet: A unit of data. Contains header (addressing info) + payload (actual data).
  • Frame: Layer 2 packet. Contains source/destination MAC addresses.
  • Segment: Layer 4 (TCP) unit. Contains port numbers and sequence numbers.
  • Datagram: Layer 4 (UDP) unit. Connectionless, unreliable.
  • Node: Any device connected to the network.
  • Host: A device with an IP address (computer, server, phone).
  • Client: Requests services. Server: Provides services.
  • Collision Domain: Where frames can collide. Each switch port = separate collision domain. Hub = one big collision domain.
  • Broadcast Domain: Where broadcast frames reach ALL devices. Separated by routers or VLANs.
  • Duplex: Simplex (one-way), Half-duplex (one at a time), Full-duplex (both simultaneously).

Network Architecture

  • Peer-to-Peer: No central server. Each device is both client and server. Simple, cheap, doesn't scale. Example: Windows Workgroup file sharing.
  • Client-Server: Centralized server provides services to clients. Scalable, manageable, secure. Example: AD domain, web/mail servers.

Physical port: A connector on a device (RJ-45, SFP). Logical port: A number (0–65535) identifying an application/service. Well-known: 0–1023. Registered: 1024–49151. Dynamic/Ephemeral: 49152–65535.

MAC Addresses

A 48-bit hardware address burned into every NIC. Layer 2 identity. Written as 6 hex pairs: AA:BB:CC:DD:EE:FF.

AA : BB : CC : DD : EE : FF |----OUI----|---Device ID---| First 24 bits = Manufacturer (e.g., 00:50:56 = VMware) Last 24 bits = Unique per device

Broadcast MAC: FF:FF:FF:FF:FF:FF — reaches ALL devices on LAN.

How a Switch Works

  1. Frame arrives on port 1 from source MAC AA:AA
  2. Switch records: "MAC AA:AA is on Port 1" in CAM table (MAC Address Table)
  3. Checks destination MAC in CAM table
  4. Known: forwards to that specific port only (unicast)
  5. Unknown: floods to ALL ports except source (unknown unicast flood)
  6. Over time, switch learns all MAC-to-port mappings

Routers

Layer 3 device. Connects different networks. Forwards based on IP addresses using a routing table. Each interface = separate broadcast domain. Performs NAT.

🔑 Switch vs Router: Switch connects devices within SAME network (MAC addresses). Router connects DIFFERENT networks (IP addresses). Your home "router" is actually router + switch + AP + firewall combined.

IPv6

128-bit, 8 groups of 4 hex digits: 2001:0db8:85a3:0000:0000:8a2e:0370:7334. Shortening: drop leading zeros, replace longest all-zero group with :: (once). Types: Global Unicast (2000::/3), Link-Local (fe80::/10), Unique Local (fc00::/7), Multicast (ff00::/8). No broadcast — uses multicast. NDP replaces ARP.

IP Subnetting & Routing

TheoryLab

Subnetting — Complete Method

🎯 Subnetting is the MOST TESTED networking topic. Practice until you can do it in your head.

Key Formulas

  • Subnets = 2^(bits borrowed from host)
  • Usable hosts = 2^(host bits) − 2
  • Block size = 256 − interesting octet value in mask
  • Network = first address (host bits all 0)
  • Broadcast = last address (host bits all 1)

Worked Example: 192.168.1.0/26

/26 = 26 network bits, 6 host bits
Mask = 255.255.255.192
Block size = 256 − 192 = 64
Subnets from /24: 2^(26−24) = 4
Hosts per subnet: 2^6 − 2 = 62

Subnet 1: 192.168.1.0   | Usable: .1–.62    | Bcast: .63
Subnet 2: 192.168.1.64  | Usable: .65–.126  | Bcast: .127
Subnet 3: 192.168.1.128 | Usable: .129–.190 | Bcast: .191
Subnet 4: 192.168.1.192 | Usable: .193–.254 | Bcast: .255

"Find the Network" Method

Q: What network does 172.16.45.200/21 belong to?

/21 mask = 255.255.248.0 → Block = 256−248 = 8 (3rd octet)
Multiples of 8: 0, 8, 16, 24, 32, 40, 48...
45 falls between 40 and 48
Network = 172.16.40.0/21   Broadcast = 172.16.47.255
Usable:  172.16.40.1 – 172.16.47.254

Networking Tools, DNS, DHCP & ARP

TheoryLab

DNS — Domain Name System (Port 53)

www.google.com → IP? 1. Browser cache → OS cache → hosts file → miss 2. Recursive Resolver (ISP / 8.8.8.8) 3. → Root Server (.) → "Try .com TLD" 4. → .com TLD Server → "Try ns1.google.com" 5. → Authoritative NS → "IP = 142.250.x.x" 6. Cache + return to browser

Records: A (→IPv4), AAAA (→IPv6), CNAME (alias), MX (mail), NS (nameserver), PTR (reverse), SOA (zone authority), TXT (SPF/DKIM), SRV (service).

DHCP (Ports 67/68, UDP)

D — Discover (broadcast: "I need an IP!") O — Offer (server: "Use 192.168.1.50") R — Request (broadcast: "I'll take .50") A — Acknowledge (confirmed, lease 8 hours)

Provides: IP, Mask, Gateway, DNS, Domain, Lease time. DHCP Relay: forwards broadcasts across routers.

ARP (Layer 2.5)

PC-A needs MAC for 192.168.1.50: 1. ARP Request (broadcast): "Who has 192.168.1.50?" 2. ARP Reply (unicast): "I do! My MAC is BB:BB:BB:BB:BB:BB" 3. PC-A caches: 192.168.1.50 → BB:BB:BB:BB:BB:BB

NAT — Network Address Translation

TheoryLab

Why NAT?

Not enough IPv4 addresses. NAT lets multiple devices share ONE public IP by translating private→public at the router.

Inside (Private) Router (NAT) Internet 192.168.1.10 ──┐ 192.168.1.20 ──┼── Router ──── 203.0.113.5 ──── Internet 192.168.1.30 ──┘ (all appear as 203.0.113.5)

NAT Types

TypeHowUse
Static NAT1 private ↔ 1 public (permanent)Web server with fixed public IP
Dynamic NATPool of public IPs, assigned on demandMultiple users, limited public IPs
PAT / OverloadMany private → 1 public (port numbers differentiate)Home/office — most common!

Terminology

Inside Local: Private IP (192.168.1.10). Inside Global: Public IP representing internal device (203.0.113.5). Outside Global: Real IP of external server (8.8.8.8).

Cisco NAT Configuration

# Mark interfaces
Router(config)# int Gi0/0
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# ip nat inside
Router(config)# int Gi0/1
Router(config-if)# ip address 203.0.113.1 255.255.255.0
Router(config-if)# ip nat outside

# ═══ Static NAT ═══
Router(config)# ip nat inside source static 192.168.1.100 203.0.113.10

# ═══ Dynamic NAT ═══
Router(config)# ip nat pool MYPOOL 203.0.113.10 203.0.113.20 netmask 255.255.255.0
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
Router(config)# ip nat inside source list 1 pool MYPOOL

# ═══ PAT (Most Common) ═══
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
Router(config)# ip nat inside source list 1 interface Gi0/1 overload

# Verify
Router# show ip nat translations
Router# show ip nat statistics
PAT — How port numbers differentiate: PC1 (192.168.1.10:50001) → NAT → (203.0.113.5:50001) → google.com PC2 (192.168.1.20:50002) → NAT → (203.0.113.5:50002) → google.com PC3 (192.168.1.30:50001) → NAT → (203.0.113.5:50003) → google.com ↑ port changed to avoid conflict

VLANs — Complete Deep Dive

TheoryLabSelf-Learn

Why VLANs?

Security: Isolate departments. Performance: Smaller broadcast domains. Flexibility: Logical grouping regardless of physical location. Policy: Apply ACLs/QoS per VLAN.

VLAN Types

  • Data VLAN: Normal user traffic
  • Voice VLAN: VoIP (QoS prioritized)
  • Management VLAN: Switch/router management (don't use VLAN 1!)
  • Native VLAN: Untagged traffic on trunk. Default=VLAN 1. Change for security!

Access vs Trunk Ports

Access: ONE VLAN, connects end devices, frames untagged. Trunk: MULTIPLE VLANs between switches, uses 802.1Q tagging (4-byte tag with VLAN ID inserted into frame).

802.1Q Tagged Frame: [Dst MAC][Src MAC][802.1Q Tag][EtherType][Data][FCS] │ ┌──────┴──────┐ │ TPID: 0x8100│ (identifies as tagged) │ Priority: 3 │ (QoS 0-7) │ VLAN ID: 10 │ (1-4094) └─────────────┘

ACLs — Access Control Lists

TheoryLabSelf-Learn

What Are ACLs?

Rules on a router that permit or deny traffic based on criteria. Most basic network filtering.

TypeNumberFiltersPlace Near
Standard1–99Source IP onlyDestination
Extended100–199Source/Dest IP, Port, ProtocolSource
NamedTextSame as Standard or ExtendedSame rules

Wildcard Masks (Inverse of Subnet Mask)

255.255.255.0   → Wildcard: 0.0.0.255      (match network)
255.255.255.128 → Wildcard: 0.0.0.127
Host exact      → Wildcard: 0.0.0.0        (keyword: host)
Any IP          → Wildcard: 255.255.255.255 (keyword: any)

ACL Rules

  • Processed top-to-bottom, first match wins
  • Implicit deny all at the end (always add permit any if needed)
  • More specific rules FIRST
  • One ACL per interface per direction

Practical

# ═══ Standard ACL — Block Source ═══
Router(config)# access-list 10 deny 192.168.10.0 0.0.0.255
Router(config)# access-list 10 permit any
Router(config)# int Gi0/1
Router(config-if)# ip access-group 10 out

# ═══ Extended ACL — Block Specific Traffic ═══
Router(config)# access-list 100 deny tcp 192.168.10.0 0.0.0.255 host 192.168.20.100 eq 80
Router(config)# access-list 100 deny tcp 192.168.10.0 0.0.0.255 host 192.168.20.100 eq 443
Router(config)# access-list 100 permit ip any any
Router(config)# int Gi0/0
Router(config-if)# ip access-group 100 in

# ═══ Named ACL ═══
Router(config)# ip access-list extended BLOCK_HR
Router(config-ext-nacl)# deny tcp 192.168.10.0 0.0.0.255 host 192.168.20.100 eq 80
Router(config-ext-nacl)# permit ip any any

# ═══ Verify ═══
Router# show access-lists
Router# show ip interface Gi0/0

🔶 Self-Learning: ACL Placement

Standard ACL → near DESTINATION (can only filter source)
  Place at source = blocks ALL traffic from source to everywhere

Extended ACL → near SOURCE (can specify destination)
  Place early = saves bandwidth, blocks only specific traffic

Rule Order:
  ✗ WRONG: permit any → deny tcp...   (deny never reached!)
  ✓ RIGHT: deny tcp... → permit any   (specific first)

NTP & Port SPAN (Mirroring)

TheoryLab

NTP — Network Time Protocol (Port 123, UDP)

Synchronizes clocks across network devices. Why critical: Log correlation for forensics, Kerberos auth fails if >5 min skew, Scheduled tasks depend on correct time.

NTP Stratum

Stratum 0: Atomic clocks/GPS. Stratum 1: Directly connected to Stratum 0. Stratum 2: Syncs to Stratum 1. Each level adds ~1ms. Stratum 16 = unsynchronized.

# Cisco NTP Client
Router(config)# ntp server 216.239.35.0
Router# show ntp status
Router# show ntp associations
Router# show clock

# Cisco NTP Server
Router(config)# ntp master 3              ! Act as Stratum 3 server

# Linux (chrony)
$ sudo systemctl enable --now chronyd
$ chronyc sources -v
$ timedatectl

Port SPAN / Port Mirroring

Copies traffic from source port(s) to a destination port for monitoring (IDS, Wireshark, SIEM).

PC ──[Port 1]──Switch──[Port 2]── Server │ [Port 24] ← SPAN destination │ [Wireshark/IDS] (sees ALL traffic)

Types: Local SPAN (same switch), RSPAN (across switches via RSPAN VLAN), ERSPAN (over L3/GRE tunnel).

# Configure Local SPAN
Switch(config)# monitor session 1 source interface Fa0/1 both
Switch(config)# monitor session 1 destination interface Fa0/24
# Or mirror entire VLAN:
Switch(config)# monitor session 1 source vlan 10
Switch# show monitor session 1

Wireshark — Capture & Filtering

TheoryLabSelf-Learn

What is Wireshark?

World's most popular packet analyzer. Captures live traffic, inspects every byte at every layer. Free and open-source. Used for troubleshooting, security analysis, forensics, and learning.

Capture Filters vs Display Filters

💡 Capture filters = BEFORE capture (BPF syntax, limits what's saved). Display filters = AFTER capture (Wireshark syntax, filter what you see). Display filters are more commonly used.

Capture Filters (BPF Syntax)

host 192.168.1.10                    # Only this IP
port 80                             # Only HTTP
tcp port 443                        # Only HTTPS
net 192.168.1.0/24                  # Only this subnet
not port 22                         # Exclude SSH

Display Filters (Wireshark Syntax)

# By Protocol
icmp                                 # Ping traffic
tcp                                  # All TCP
udp                                  # All UDP
http                                 # HTTP only
dns                                  # DNS queries/responses
arp                                  # ARP
tls                                  # TLS/SSL
dhcp                                 # DHCP

# By IP
ip.addr == 192.168.1.10              # To or from this IP
ip.src == 192.168.1.10               # FROM this IP
ip.dst == 8.8.8.8                    # TO this IP

# By Port
tcp.port == 80                       # Port 80 either direction
tcp.dstport == 443                   # Destination port 443
udp.port == 53                       # DNS

# By TCP Flags
tcp.flags.syn == 1                   # SYN packets
tcp.flags.syn == 1 && tcp.flags.ack == 0  # SYN only (new connections)
tcp.flags.rst == 1                   # Reset packets
tcp.flags.fin == 1                   # Connection close

# Combining
ip.src == 192.168.1.10 && tcp.dstport == 80
http.request.method == "GET"
http.response.code == 404
dns.qry.name contains "google"
tcp.analysis.retransmission          # Retransmissions (trouble indicator)

# Exclusion
!(arp || dns)                        # Exclude ARP and DNS noise
!ip.addr == 10.0.0.1                 # Exclude this IP

Essential Wireshark Features

  • Follow TCP Stream: Right-click → Follow → TCP Stream (read full conversation)
  • Protocol Hierarchy: Statistics → Protocol Hierarchy (% breakdown)
  • Conversations: Statistics → Conversations (who talked to whom)
  • Expert Info: Analyze → Expert Information (warnings, errors)
  • IO Graph: Statistics → IO Graph (traffic over time)
  • Coloring: Green=TCP, Blue=DNS, Red=Errors, etc.

3-Way Handshake in Wireshark

# Filter: tcp.flags.syn == 1

Pkt 1: [SYN]       Client→Server  Seq=0                Flags: SYN
Pkt 2: [SYN,ACK]   Server→Client  Seq=0, Ack=1         Flags: SYN+ACK
Pkt 3: [ACK]       Client→Server  Seq=1, Ack=1         Flags: ACK
                    ═══ Connection Established ═══
Pkt 4: [PSH,ACK]   Client→Server  Seq=1, Len=374       (HTTP GET)
Pkt 5: [ACK]       Server→Client  Ack=375              (confirms 374 bytes)

Key: ACK# = last Seq received + data length

UDP Header (Fixed 8 bytes)

Source Port (16) + Dest Port (16) + Length (16) + Checksum (16) = 8 bytes total. No sequence numbers, no ACK, no handshake. Just data. That's why it's fast.

🔶 Self-Learning: Wireshark Analysis Tasks

# Capture ICMP:  Filter: icmp
# - Identify Type 8 (Echo Request) and Type 0 (Echo Reply)
# - Note TTL values (64 = Linux, 128 = Windows)

# Capture TCP handshake:  Filter: tcp.flags.syn == 1
# - Identify SYN, SYN-ACK, ACK sequence
# - Note initial sequence numbers (ISN)
# - Observe window size negotiation

# Capture HTTP:  Filter: http
# - Find GET requests (http.request.method == "GET")
# - Follow TCP Stream → read full request/response

# Capture DNS:  Filter: dns
# - See query (dns.flags.response == 0)
# - See response (dns.flags.response == 1)
# - Note: A record responses contain IP

# Compare IPv4 vs IPv6:
# Filter: ip       (IPv4 packets — check TTL, Protocol fields)
# Filter: ipv6     (IPv6 packets — check Hop Limit, Next Header)

Installation

  1. Download from gns3.com
  2. Install GNS3 application (includes Dynamips, VPCS)
  3. Install GNS3 VM (VMware/VirtualBox) — recommended for heavy appliances
  4. Start GNS3 → Setup Wizard → "Run appliances on GNS3 VM"

GNS3 Components

  • Dynamips: Emulates Cisco IOS routers (needs real .bin images)
  • VPCS: Lightweight virtual PCs (ping, traceroute only)
  • QEMU: Full OS emulation (Juniper vSRX, Linux, Windows)
  • Docker: Lightweight containers for Linux tools
  • GNS3 VM: Dedicated VM for heavy emulation workload

GUI Layout

Center: Topology workspace. Left: Device toolbar (routers, switches, end devices, links). Right: Server summary (CPU/RAM). Bottom: Console, logs.

Idle-PC (Critical!)

Without Idle-PC, each emulated router uses 100% CPU. Right-click router → Idle-PC → Select value with * (asterisk = recommended). This pauses emulation when router is idle, dramatically reducing CPU usage.
