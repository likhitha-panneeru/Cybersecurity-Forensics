Installing Windows Server 2019 & Post-Installation Tasks

TheoryLab

Theory — Windows Server 2019 Overview

What is Windows Server?

Windows Server is Microsoft's operating system designed for servers — machines that provide services to other computers (clients) on a network. Unlike Windows 10/11 (designed for desktops), Windows Server is built for:

  • Hosting websites (IIS), email, databases, file shares
  • Managing users and devices across an organization (Active Directory)
  • Running 24/7 with high reliability, security, and scalability

Windows Server 2019 Editions

EditionUse CaseKey Details
EssentialsSmall business (≤25 users)No Hyper-V, Simplified, Max 64 GB RAM
StandardNon-virtualized / Light virtualizationIncludes 2 VM licenses, Full features
DatacenterHeavy virtualization / CloudUnlimited VMs, Shielded VMs, Storage Spaces Direct, Software-Defined Networking

Installation Types

  • Desktop Experience (GUI): Full graphical interface. Easier to manage visually. Uses more resources. Best for beginners and roles that need GUI (like IIS Manager).
  • Server Core: Command-line only, no GUI. Uses less RAM/CPU/disk. Smaller attack surface (fewer components = fewer vulnerabilities). Managed via PowerShell, sconfig tool, or remote tools (RSAT). Microsoft's recommended installation for production.
  • Nano Server: Minimal footprint, container-focused. No local logon. Managed entirely remotely.

Installation Methods

  • Clean install: From ISO/USB to bare metal or VM. Most common.
  • Upgrade: From older Windows Server version (2012 R2 → 2016 → 2019).
  • Unattended: Using an answer file (unattend.xml) for automated deployment. No user interaction needed. Used for deploying many servers.
  • WDS (Windows Deployment Services): Network-based deployment via PXE boot. Server hosts the image, clients boot from network and install.

Post-Installation Tasks (Critical!)

After installing Windows Server, you MUST configure these before putting it into production:

  1. Set a static IP address: Servers should NEVER use DHCP — their IP must be fixed so clients can always find them. 
    # PowerShell — Set static IP
New-NetIPAddress -InterfaceIndex 12 -IPAddress 192.168.1.10 -PrefixLength 24 -DefaultGateway 192.168.1.1
Set-DnsClientServerAddress -InterfaceIndex 12 -ServerAddresses 8.8.8.8,8.8.4.4
  2. Set hostname: Give the server a meaningful name (e.g., DC01, WEB01, FILE01). 
    # PowerShell
Rename-Computer -NewName "DC01" -Restart
  3. Configure time synchronization: Critical for Active Directory and Kerberos authentication (time skew >5 min = auth failure). 
    # PowerShell
w32tm /config /manualpeerlist:"time.windows.com" /syncfromflags:manual /reliable:YES /update
w32tm /resync
  4. Windows Update: Install all security patches immediately.
  5. Enable Remote Desktop: So you can manage the server remotely. 
    # PowerShell
Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name "fDenyTSConnections" -Value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"
  6. Configure Windows Firewall: Open only needed ports, block everything else.
  7. Disable unnecessary services: Reduce attack surface. Disable services you don't need.
  8. Activate Windows: Enter product key or connect to KMS server.
  9. Verify using PowerShell and Event Viewer: 
    # Check system info
Get-ComputerInfo | Select CsName, WindowsVersion, OsArchitecture
# Check event logs for errors
Get-EventLog -LogName System -EntryType Error -Newest 10

What Is WPS (Windows PowerShell)?

PowerShell is Microsoft's command-line shell and scripting language. It uses cmdlets (Verb-Noun format). Much more powerful than Command Prompt (cmd). Examples:

# Basic cmdlets
Get-Help Get-Service          # Help on a cmdlet
Get-Service                   # List all services
Get-Process | Sort CPU -Desc  # Processes by CPU usage
Get-EventLog -LogName Security -Newest 20
Get-NetIPAddress              # IP addresses
Test-NetConnection google.com -Port 443  # Test connectivity

Directory Services — Active Directory (AD DS)

TheoryLab

Theory — Active Directory

What is Active Directory (AD)?

Active Directory is Microsoft's directory service — a centralized database that stores information about all the resources in your network (users, computers, printers, groups, policies). Think of it as a phone book for your entire organization — but instead of just phone numbers, it stores usernames, passwords, permissions, computer configurations, and security policies.

💡 Without AD: Each computer manages its own users locally. With 100 employees, you'd need to create accounts on each PC separately. With AD: Create one account → user can log in to ANY computer on the network. Change password once → it's updated everywhere. Instant.

Key AD Components

  • Domain: The fundamental unit. A collection of objects (users, computers, groups) that share a common database and security policies. Example: cdac.local.
  • Domain Controller (DC): A server running AD DS. It authenticates users (verifies username/password) and enforces policies. Every domain needs at least one DC. Two DCs recommended for redundancy.
  • Forest: The top-level container. One or more domains that share a common schema, configuration, and global catalog. The first domain created becomes the Forest Root Domain.
  • Tree: A hierarchy of domains with contiguous namespace (e.g., cdac.local → training.cdac.local → cyber.training.cdac.local).
  • Organizational Unit (OU): A container within a domain for organizing objects. You can apply Group Policies to OUs. Example: OU=HR, OU=Finance, OU=IT.
  • Objects: Users, Groups, Computers, Printers, Contacts, Shared Folders.

AD DS vs DNS Relationship

AD depends heavily on DNS. When a computer joins a domain, it uses DNS to find the Domain Controller. DNS stores SRV records that point to DCs. Without DNS, AD doesn't work. That's why the DNS role is almost always installed alongside AD DS.

LDAP (Lightweight Directory Access Protocol)

The protocol used to query and modify Active Directory. Port 389 (LDAP), Port 636 (LDAPS — encrypted). Objects are identified by their Distinguished Name (DN):

CN=John Smith,OU=IT,DC=cdac,DC=local
│         │        │
│         │        └─ Domain: cdac.local
│         └─ Organizational Unit: IT
└─ Common Name: John Smith

Trusts

Trusts allow users in one domain to access resources in another domain.

  • One-way: Domain A trusts Domain B → B's users can access A's resources (not vice versa).
  • Two-way: Both domains trust each other (default within a forest).
  • Transitive: If A trusts B and B trusts C, then A trusts C (automatic within a forest).
  • Non-transitive: Trust doesn't extend beyond the two domains.

FSMO Roles (Flexible Single Master Operations)

5 special roles that can only be held by one DC at a time:

RoleLevelPurpose
Schema MasterForest-wide (1)Controls changes to the AD schema (structure)
Domain Naming MasterForest-wide (1)Controls adding/removing domains in the forest
RID MasterDomain-wide (1)Allocates pools of Relative IDs for SID creation
PDC EmulatorDomain-wide (1)Password changes, Time sync, Backward compatibility
Infrastructure MasterDomain-wide (1)Tracks cross-domain group membership changes

Replication

If you have multiple DCs (you should), changes made on one DC are replicated to all others. Intra-site replication: Within same physical site — fast, frequent (15 seconds). Inter-site replication: Between sites — scheduled, compressed, uses less bandwidth.

SYSVOL: Shared folder on every DC that stores Group Policy objects and logon scripts. Replicated using DFS-R.

Practical — Installing AD DS

# Step 1: Install AD DS role via PowerShell
Install-WindowsFeature AD-Domain-Services -IncludeManagementTools

# Step 2: Promote server to Domain Controller
Install-ADDSForest `
  -DomainName "cdac.local" `
  -DomainNetBIOSName "CDAC" `
  -ForestMode "WinThreshold" `
  -DomainMode "WinThreshold" `
  -InstallDns:$true `
  -SafeModeAdministratorPassword (ConvertTo-SecureString "P@ssw0rd!" -AsPlainText -Force) `
  -Force:$true
# Server will restart automatically

# Step 3: Verify
Get-ADDomainController
Get-ADDomain
Get-ADForest

# Step 4: Create OUs
New-ADOrganizationalUnit -Name "HR" -Path "DC=cdac,DC=local"
New-ADOrganizationalUnit -Name "Finance" -Path "DC=cdac,DC=local"
New-ADOrganizationalUnit -Name "IT" -Path "DC=cdac,DC=local"

# Step 5: Create Users
New-ADUser -Name "John Smith" -SamAccountName "jsmith" `
  -UserPrincipalName "jsmith@cdac.local" `
  -Path "OU=IT,DC=cdac,DC=local" `
  -AccountPassword (ConvertTo-SecureString "Welcome@123" -AsPlainText -Force) `
  -Enabled $true

# Step 6: Create Groups
New-ADGroup -Name "IT-Admins" -GroupScope Global -GroupCategory Security `
  -Path "OU=IT,DC=cdac,DC=local"
Add-ADGroupMember -Identity "IT-Admins" -Members "jsmith"

# Step 7: Validate replication health
repadmin /replsummary
repadmin /showrepl
dcdiag /v

Server Roles (IIS, RDS) & Group Policy (GPO)

Theory — Server Roles

Windows Server uses a role-based architecture. A "role" is a major function the server performs. You add only the roles you need — keeping the server lean and secure.

IIS (Internet Information Services)

Microsoft's web server. Hosts websites and web applications (ASP.NET, PHP). Equivalent of Apache/Nginx on Linux.

# Install IIS
Install-WindowsFeature Web-Server -IncludeManagementTools
# Verify — open browser → http://localhost → Default IIS page appears
# IIS Manager: inetmgr

Key concepts: Sites (websites hosted), Application Pools (process isolation), Bindings (hostname, IP, port, SSL), Virtual Directories, HTTPS/SSL configuration.

RDS (Remote Desktop Services)

Allows users to remotely access applications or full desktops hosted on the server. Components: RD Session Host (hosts sessions), RD Connection Broker (load balancing), RD Web Access (web portal), RD Gateway (HTTPS tunneling for external access), RD Licensing.

# Install RDS
Install-WindowsFeature RDS-RD-Server -IncludeManagementTools

Theory — Group Policy (GPO)

What is Group Policy?

Group Policy lets administrators centrally manage settings for users and computers across the entire domain. Instead of configuring each computer individually, you create a policy once and it automatically applies to all targeted users/computers.

💡 Example: Want to set a password policy requiring 12+ characters for everyone? Don't configure each PC — create one GPO, link it to the domain, and it applies to ALL users automatically.

GPO Structure

  • Computer Configuration: Settings that apply to the MACHINE regardless of who logs in. Examples: Firewall rules, Windows Update settings, Security settings, Startup scripts.
  • User Configuration: Settings that apply to the USER regardless of which machine they log into. Examples: Desktop wallpaper, Start menu restrictions, Drive mappings, Logon scripts.

GPO Processing Order — LSDOU

When multiple GPOs exist, they apply in this order (later = higher priority):

  1. Local GPO (on the machine itself)
  2. Site GPO (linked to AD Site)
  3. Domain GPO (linked to the domain — e.g., Default Domain Policy)
  4. OU GPO (linked to OU — closest OU wins)

Last applied wins if there's a conflict. You can override with: Enforce (No Override — makes a higher-level GPO take priority) and Block Inheritance (OU ignores parent GPOs).

Key GPO Settings for Security

  • Password Policy: Min length (12+), Complexity, Max age (90 days), History (24)
  • Account Lockout: Threshold (5 attempts), Duration (30 min), Reset counter (30 min)
  • Audit Policy: Log success/failure for logon events, object access, account management
  • User Rights Assignment: Who can log on locally, remotely, shut down system
  • Software Restriction: AppLocker, Software Restriction Policies
  • Windows Firewall: Configure firewall rules via GPO

Advanced GPO Concepts

  • Security Filtering: Apply GPO only to specific users/groups (instead of everyone in the OU).
  • WMI Filtering: Apply GPO only if a WMI condition is true (e.g., only Windows 10 machines, only laptops).
  • Loopback Processing: Applies User Configuration settings based on the COMPUTER's location, not the user's. Two modes: Replace (ignores user's normal GPOs) and Merge (applies both). Used for kiosks, shared workstations.

Practical

DNS — Domain Name System (In Depth)

TheoryLab

Theory — DNS Explained

DNS translates human-readable names (www.cdac.in) to IP addresses (14.139.34.3). Without DNS, you'd need to memorize IP addresses for every website. DNS uses port 53 (UDP for queries, TCP for zone transfers and large responses).

DNS Hierarchy

. (Root) / | \ .com .in .org ← TLD (Top-Level Domain) / | google.com cdac.in ← Second-Level Domain / | www.google.com www.cdac.in ← Subdomain (FQDN)

DNS Zone Types

  • Forward Lookup Zone: Name → IP (most common). "What is the IP of www.cdac.in?"
  • Reverse Lookup Zone: IP → Name (PTR records). "What name does 192.168.1.10 have?"
  • Primary Zone: Read-write copy. Only one primary per zone.
  • Secondary Zone: Read-only copy. Gets data from primary via zone transfer.
  • Stub Zone: Contains only NS and SOA records. Points to authoritative servers.
  • AD-Integrated Zone: Stored in Active Directory (not zone files). Replicated with AD replication. Supports secure dynamic updates. Recommended for AD environments.

DNS Record Types

RecordPurposeExample
AHostname → IPv4 addresswebserver → 192.168.1.50
AAAAHostname → IPv6 addresswebserver → 2001:db8::50
CNAMEAlias (one name → another name)www → webserver.cdac.local
MXMail server for domaincdac.local → mail.cdac.local (priority 10)
NSAuthoritative nameservercdac.local → dc01.cdac.local

Practical — DNS Lab

# Create a new A (Host) record
Add-DnsServerResourceRecordA -ZoneName "cdac.local" -Name "webserver" -IPv4Address "192.168.1.50"

# Create a CNAME (Alias) record
Add-DnsServerResourceRecordCName -ZoneName "cdac.local" -Name "www" -HostNameAlias "webserver.cdac.local"

# Create an MX record (for Exchange)
Add-DnsServerResourceRecordMX -ZoneName "cdac.local" -Name "." -MailExchange "mail.cdac.local" -Preference 10

# Create a PTR record (reverse)
Add-DnsServerResourceRecordPtr -ZoneName "1.168.192.in-addr.arpa" -Name "50" -PtrDomainName "webserver.cdac.local"

# View all records in a zone
Get-DnsServerResourceRecord -ZoneName "cdac.local"

# DNS Troubleshooting
nslookup webserver.cdac.local
nslookup -type=mx cdac.local
nslookup -type=soa cdac.local
ipconfig /flushdns                  # Clear client DNS cache
ipconfig /displaydns                # Show client DNS cache
Clear-DnsServerCache                # Clear server DNS cache

# Test DNS resolution
Resolve-DnsName webserver.cdac.local
Resolve-DnsName -Name cdac.local -Type MX

DNS Security (Interview Important)

Attacks: DNS Spoofing/Cache Poisoning (fake responses), DNS Amplification (DDoS), DNS Tunneling (data exfiltration over DNS), DNS Hijacking, Zone Transfer abuse.

Defenses: DNSSEC (cryptographic signatures), Restrict zone transfers (to specific IPs only), Disable recursion on authoritative servers, Rate limiting, DNS logging and monitoring.

Managing DNS & Caching Nameserver (Unbound)

TheoryLab

Theory — DNS Server Management

Recursive vs Authoritative

Recursive (Caching) DNS: Resolves queries on behalf of clients by querying other DNS servers. Caches results for faster subsequent lookups. Examples: Your ISP's DNS, Google (8.8.8.8), Cloudflare (1.1.1.1). Authoritative DNS: Holds the actual DNS records for a domain. Answers "I know the answer" vs "Let me find out for you."

Unbound — Caching Nameserver

Unbound is a popular open-source recursive DNS resolver for Linux. It caches DNS queries locally for faster resolution and can validate DNSSEC.

Practical

# Install Unbound (CentOS/RHEL)
$ sudo yum install unbound

# Configure /etc/unbound/unbound.conf
server:
    interface: 0.0.0.0            # Listen on all interfaces
    access-control: 192.168.1.0/24 allow   # Allow local network
    do-ip6: no
    hide-identity: yes
    hide-version: yes
    val-clean-additional: yes     # DNSSEC validation

forward-zone:
    name: "."
    forward-addr: 8.8.8.8        # Forward to Google DNS
    forward-addr: 8.8.4.4

# Start and enable
$ sudo systemctl enable --now unbound

# Test
$ dig @127.0.0.1 google.com
$ unbound-control stats                     # Cache statistics

# DNS Troubleshooting commands
$ nslookup domain.com
$ dig domain.com +trace                     # Full resolution path
$ dig domain.com @8.8.8.8                   # Query specific server
$ host domain.com
$ systemd-resolve --status                  # systemd DNS info

DHCP Server

TheoryLab

Theory — DHCP

DHCP (Dynamic Host Configuration Protocol) automatically assigns IP addresses and network configuration to devices. Without DHCP, you'd have to manually configure IP, subnet mask, gateway, and DNS on every single device.

DORA Process

Client (no IP yet) DHCP Server |--- DISCOVER (broadcast) -------->| "I need an IP!" |<----- OFFER ----------------------| "How about 192.168.1.50?" |--- REQUEST (broadcast) --------->| "OK, I'll take that one" |<-- ACKNOWLEDGE ------------------| "Done. Lease: 8 hours"

DHCP Components

  • Scope: Range of IP addresses the server can assign (e.g., 192.168.1.100 – 192.168.1.200)
  • Exclusion: IPs within the scope that should NOT be assigned (e.g., printers, servers with static IPs)
  • Reservation: Permanently assign a specific IP to a specific MAC address (e.g., a printer always gets .50)
  • Lease Duration: How long a client can use the assigned IP before renewing
  • Scope Options: Gateway (option 3), DNS server (option 6), Domain name (option 15)

DHCP Failover

Two DHCP servers sharing a scope for redundancy. Modes: Hot Standby (one active, one standby — takes over if primary fails) and Load Balance (both active, split the load 50/50).

Practical

# Install DHCP role
Install-WindowsFeature DHCP -IncludeManagementTools

# Authorize DHCP in AD
Add-DhcpServerInDC -DnsName "dc01.cdac.local" -IPAddress 192.168.1.10

# Create a scope
Add-DhcpServerv4Scope -Name "Main Office" -StartRange 192.168.1.100 -EndRange 192.168.1.200 `
  -SubnetMask 255.255.255.0 -LeaseDuration 08:00:00 -State Active

# Set scope options
Set-DhcpServerv4OptionValue -ScopeId 192.168.1.0 -DnsDomain "cdac.local" `
  -DnsServer 192.168.1.10 -Router 192.168.1.1

# Create a reservation (printer always gets .50)
Add-DhcpServerv4Reservation -ScopeId 192.168.1.0 -IPAddress 192.168.1.50 `
  -ClientId "00-11-22-33-44-55" -Name "Printer01"

# Create exclusion
Add-DhcpServerv4ExclusionRange -ScopeId 192.168.1.0 -StartRange 192.168.1.1 -EndRange 192.168.1.20

# Configure failover
Add-DhcpServerv4Failover -Name "DC01-DC02-Failover" -PartnerServer "dc02.cdac.local" `
  -ScopeId 192.168.1.0 -SharedSecret "S3cret!" -Mode LoadBalance

# View leases
Get-DhcpServerv4Lease -ScopeId 192.168.1.0

# Troubleshoot
ipconfig /release
ipconfig /renew
Get-DhcpServerv4ScopeStatistics

Disk Types

Storage Spaces

Windows Server feature that pools physical disks into a storage pool, then creates virtual disks with redundancy. Types: Simple (no redundancy, like RAID 0), Mirror (copies, like RAID 1), Parity (like RAID 5). Storage Spaces Direct (S2D): Software-defined storage across multiple servers — Datacenter edition only.

Firewall Administration & Disaster Recovery

TheoryLab

Windows Firewall

Windows Defender Firewall with Advanced Security — built-in host-based firewall. Controls inbound/outbound traffic based on rules. Has three profiles: Domain (connected to AD domain), Private (trusted network), Public (untrusted network).

Practical — Firewall

# Open Firewall GUI
wf.msc

# PowerShell — Allow inbound port
New-NetFirewallRule -DisplayName "Allow HTTP" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
New-NetFirewallRule -DisplayName "Allow HTTPS" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow
New-NetFirewallRule -DisplayName "Allow RDP" -Direction Inbound -Protocol TCP -LocalPort 3389 -Action Allow

# Block an IP
New-NetFirewallRule -DisplayName "Block Attacker" -Direction Inbound -RemoteAddress 10.10.10.100 -Action Block

# List all rules
Get-NetFirewallRule | Where {$_.Enabled -eq $true} | Format-Table DisplayName, Direction, Action

# Using netsh
netsh advfirewall firewall add rule name="Allow SSH" dir=in action=allow protocol=tcp localport=22
netsh advfirewall firewall show rule name=all
netsh advfirewall set allprofiles state on

# Enable logging
Set-NetFirewallProfile -Profile Domain -LogFileName "C:\Windows\System32\LogFiles\Firewall\pfirewall.log" -LogMaxSizeKilobytes 4096 -LogAllowed True -LogBlocked True

Disaster Recovery

DSRM (Directory Services Restore Mode)

A special boot mode for DCs to repair/restore Active Directory. Used when AD is corrupted and you need to restore from backup. DSRM password is set during AD DS promotion — must be documented securely.

# Reset DSRM password
ntdsutil
> set dsrm password
> reset password on server null
> (enter new password)
> quit

Windows Server Backup

# Install backup feature
Install-WindowsFeature Windows-Server-Backup

# Backup system state (includes AD, registry, boot files)
wbadmin start systemstatebackup -backuptarget:E:

# Full server backup
wbadmin start backup -backuptarget:E: -include:C: -allCritical -quiet

# Registry backup and restore
reg export HKLM\System C:\Backups\system_reg.reg
reg import C:\Backups\system_reg.reg

Basic Shell Programming

#!/bin/bash
# disk_memory_monitor.sh — Checks disk and memory usage, alerts if high

THRESHOLD=80
DATE=$(date '+%Y-%m-%d %H:%M:%S')
LOGFILE="/var/log/system_monitor.log"

echo "=== System Monitor Report — $DATE ===" | tee -a $LOGFILE

# Check disk usage
echo "--- Disk Usage ---" | tee -a $LOGFILE
df -h | grep -vE "tmpfs|devtmpfs" | while read line; do
    USAGE=$(echo $line | awk '{print $5}' | tr -d '%')
    MOUNT=$(echo $line | awk '{print $6}')
    if [ ! -z "$USAGE" ] && [ "$USAGE" -gt "$THRESHOLD" ] 2>/dev/null; then
        echo "⚠️  ALERT: $MOUNT is at ${USAGE}% usage!" | tee -a $LOGFILE
    fi
done

# Check memory usage
MEM_TOTAL=$(free | grep Mem | awk '{print $2}')
MEM_USED=$(free | grep Mem | awk '{print $3}')
MEM_PERCENT=$((MEM_USED * 100 / MEM_TOTAL))
echo "--- Memory: ${MEM_PERCENT}% used ---" | tee -a $LOGFILE
if [ "$MEM_PERCENT" -gt "$THRESHOLD" ]; then
    echo "⚠️  ALERT: Memory usage is at ${MEM_PERCENT}%!" | tee -a $LOGFILE
fi

echo "Report saved to $LOGFILE"

# Make executable:
$ chmod +x disk_memory_monitor.sh
$ ./disk_memory_monitor.sh

# Schedule with cron (run every hour):
$ crontab -e
0 * * * * /opt/scripts/disk_memory_monitor.sh

Disk Partitions, File Systems & LVM

TheoryLab

Theory — LVM (Logical Volume Manager)

LVM adds a layer of abstraction between physical disks and file systems. Instead of fixed partitions, you get flexible, resizable volumes. This is crucial for production servers where you need to add space without downtime.

Physical Disks → Physical Volumes (PV) /dev/sdb PV on /dev/sdb /dev/sdc PV on /dev/sdc ↓ Volume Group (VG) "data_vg" (pools all PVs) ↓ Logical Volumes (LV) "lv_web" "lv_db" (50 GB) (100 GB) ↓ File Systems /var/www /var/lib/mysql

Why LVM?

  • Resize volumes live — extend a volume without unmounting or rebooting
  • Span multiple disks — combine several physical disks into one logical volume
  • Snapshots — point-in-time copy for backups
  • Easy management — add new disk, extend VG, extend LV, resize filesystem

Practical — Complete LVM Workflow

# ── Step 1: Create Physical Volumes ──
$ sudo pvcreate /dev/sdb /dev/sdc
$ sudo pvdisplay                             # Verify PVs

# ── Step 2: Create Volume Group ──
$ sudo vgcreate data_vg /dev/sdb /dev/sdc
$ sudo vgdisplay data_vg                     # Verify VG

# ── Step 3: Create Logical Volumes ──
$ sudo lvcreate -L 50G -n lv_web data_vg     # 50 GB for web
$ sudo lvcreate -L 100G -n lv_db data_vg     # 100 GB for database
$ sudo lvdisplay                             # Verify LVs

# ── Step 4: Create File Systems ──
$ sudo mkfs.xfs /dev/data_vg/lv_web
$ sudo mkfs.ext4 /dev/data_vg/lv_db

# ── Step 5: Mount ──
$ sudo mkdir -p /var/www /var/lib/mysql
$ sudo mount /dev/data_vg/lv_web /var/www
$ sudo mount /dev/data_vg/lv_db /var/lib/mysql

# ── Step 6: Make persistent (survive reboot) ──
$ echo '/dev/data_vg/lv_web  /var/www        xfs   defaults 0 0' | sudo tee -a /etc/fstab
$ echo '/dev/data_vg/lv_db   /var/lib/mysql  ext4  defaults 0 0' | sudo tee -a /etc/fstab

# Verify
$ df -h
$ mount | grep data_vg

# ══ EXTENDING A LOGICAL VOLUME (no downtime!) ══

# Add new disk to VG
$ sudo pvcreate /dev/sdd
$ sudo vgextend data_vg /dev/sdd

# Extend LV by 20 GB
$ sudo lvextend -L +20G /dev/data_vg/lv_web

# Resize filesystem to use new space
$ sudo xfs_growfs /var/www                   # For XFS (can only grow, not shrink)
$ sudo resize2fs /dev/data_vg/lv_db          # For ext4 (can grow and shrink)

# Verify
$ df -h /var/www

# ══ SWAP SPACE ══
$ sudo lvcreate -L 4G -n lv_swap data_vg
$ sudo mkswap /dev/data_vg/lv_swap
$ sudo swapon /dev/data_vg/lv_swap
$ echo '/dev/data_vg/lv_swap  swap  swap  defaults 0 0' | sudo tee -a /etc/fstab
$ free -h                                    # Verify swap

# ══ ADDING STANDARD PARTITIONS ══
$ sudo fdisk /dev/sdb                        # Interactive partitioning
# n → new partition → select type → w → write
$ sudo mkfs.ext4 /dev/sdb1
$ sudo mount /dev/sdb1 /mnt/data
# Add to /etc/fstab for persistence

# ══ ROLLBACK (if extension fails) ══
# ext4: Can shrink (unmount first, fsck, resize2fs, lvreduce)
$ sudo umount /var/lib/mysql
$ sudo e2fsck -f /dev/data_vg/lv_db
$ sudo resize2fs /dev/data_vg/lv_db 80G
$ sudo lvreduce -L 80G /dev/data_vg/lv_db
$ sudo mount /dev/data_vg/lv_db /var/lib/mysql
# XFS: Cannot shrink! Only option is backup → recreate → restore
